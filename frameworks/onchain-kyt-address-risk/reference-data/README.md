# Reference data — on-chain KYT address risk

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 800 addresses versus the 50,000 used for validation (1.6%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** One small spreadsheet of made-up blockchain addresses with their computed exposure
> features and the right answer attached, so you can see what the disposition
> engine reads before running the full 50,000-address validation.

## `addresses.csv` — 800 rows (validation scale: 50,000)

One row per screened address. Exposure features are derived by running the real taint propagation in `_lib/graph` over a constructed transaction subgraph.

| Column | Meaning |
|---|---|
| `address_id` | Unique address identifier (synthetic — not a real chain address). |
| `top_category` | Dominant exposure category (e.g. sanctioned, mixer, darknet, exchange_licensed, defi_bluechip). |
| `exposure` | Traceable exposure share to that category after propagation and decay. |
| `hops` | Graph distance from the seed to the address. |
| `amount_fraction` | Fraction of the address's value attributable to the traced path. |
| `via_breaker` | 1 if the path passes through a commingling intermediary (licensed CEX) that breaks traceability. |
| `direction` | Flow direction of the exposure (inbound / outbound). |
| `label` | Ground truth: 1 = true risk (material, proximate, unbroken exposure to a serious category); 0 = false positive. |
| `fp_category` | Construction category — named false-positive reason (benign_category, broken_intermediary, de_minimis, diluted_distant, ambiguous_residual) or true-risk flavour (clear_serious, emerging). |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only onchain-kyt-address-risk
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

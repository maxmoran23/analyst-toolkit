# Reference data — investigations case-file QA

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 700 cases versus the 50,000 used for validation (1.4%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** One small spreadsheet of made-up completed investigation files — most clean, a few
> hiding exactly one planted critical defect — so you can see what the QA engine
> reads before running the full 50,000-case validation.

## `cases.csv` — 700 rows (validation scale: 50,000)

Completed investigation case files with a KNOWN planted-deficiency ground truth.

| Column | Meaning |
|---|---|
| `case_id` | Unique case identifier. |
| `case_type` | Investigation type (alert review, SAR referral, etc.). |
| `subject_identified` | 1 if the subject is identified in the file (mandatory element). |
| `account_scope_documented` | 1 if the account scope is documented (mandatory element). |
| `lookback_days` | Documented lookback period in days (0 = absent). |
| `scope_elements_total` | Scope elements the case declared. |
| `scope_elements_reviewed` | Scope elements actually reviewed (shortfall on planted unreviewed-scope cases). |
| `evidence_item_count` | Documented evidence items on file. |
| `evidence_source_types` | Distinct evidence source types. |
| `corroborated_typology` | 1 if the file contains corroborated typology evidence. |
| `disposition` | Recorded disposition (no_finding / escalate / SAR referral, etc.). |
| `rationale_claim_count` | Factual claims made in the disposition rationale. |
| `rationale_cited_count` | Claims backed by a citation to a documented evidence item. |
| `escalation_trigger_count` | Documented escalation-trigger facts. |
| `escalation_flag` | 1 if the case flagged an escalation. |
| `alert_to_open_days` | Days from alert to case open (timeliness). |
| `open_to_complete_days` | Days from open to completion (timeliness). |
| `chronology_present` | 1 if a chronology is on file. |
| `missing_5w` | Count of missing who/what/when/where/why narrative elements. |
| `empty_narrative_fields` | Count of empty narrative fields. |
| `label` | Ground truth: 1 = planted CRITICAL deficiency (must never pass QA); 0 = non-critical. |
| `category` | Construction category — clean, minor_findings, major_findings, or the named plant (e.g. plant_uncited_disposition, plant_missed_escalation). |
| `expected_check` | For plants: the named QA check that must catch this file. |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only investigations-case-qa
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

# Reference data — fraud detection

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 150 events versus the 50,000 used for validation (0.3% — sized down further than the usual 1-5% because each JSONL event row is wide, and the pack is capped at ~150 KB). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** A small file of made-up payment events plus the customer baselines they are judged
> against, labelled with which ones are confirmed fraud, so you can see what the
> scoring engine reads before running the full 50,000-event validation.

## `baselines.json` — 150 customer baselines (validation scale: 50,000 events)

JSON object keyed by `customer_id`; one baseline per customer appearing in `events.jsonl`.

| Column | Meaning |
|---|---|
| `customer_id` | Customer identifier (matches the object key and the events file). |
| `expected_amount` | Customer's expected transaction amount (the behavioural baseline). |
| `expected_transaction_count_10m` | Expected transaction count per 10-minute window. |
| `tenure_days` | Account tenure in days. |

## `events.jsonl` — 150 events, one JSON object per line (validation scale: 50,000)

Payment events with the full feature vector the scorer consumes, labelled with ground truth.

| Column | Meaning |
|---|---|
| `event_id` | Unique event identifier. |
| `customer_id` | Customer the event belongs to (joins to `baselines.json`). |
| `amount` | Transaction amount. |
| `transaction_count_10m` | Transactions observed in the trailing 10-minute window. |
| `account_age_days` | Account age in days at event time. |
| `new_device` | 1 if the event came from a device not seen before. |
| `trusted_device` | 1 if the device is enrolled/trusted. |
| `strong_authentication` | 1 if strong authentication was completed. |
| `failed_login_count` | Recent failed login attempts. |
| `contact_change_hours` | Hours since the last contact-detail change (small values are risk-relevant). |
| `beneficiary_first_seen` | 1 if the beneficiary is first-seen for this customer. |
| `beneficiary_risk` | Beneficiary risk grade. |
| `merchant_trust` | Merchant trust grade (card events). |
| `cnp` | 1 if card-not-present. |
| `cross_border` | 1 if cross-border. |
| `inbound_amount_72h` | Inbound value received in the trailing 72 hours (mule-inflow signal). |
| `inbound_senders_72h` | Distinct inbound senders in the trailing 72 hours. |
| `same_day_outbound_amount` | Value sent back out the same day (pass-through signal). |
| `returned_payments_90d` | Returned payments in the trailing 90 days. |
| `utilization_ratio` | Credit-line utilization ratio (bust-out signal). |
| `identity_document_reused` | 1 if the identity document appears on another profile (synthetic-identity signal). |
| `identity_mismatch_count` | Count of identity-field mismatches. |
| `boundary_case` | 1 if the event was planted at a decision boundary by construction. |
| `typology` | Fraud typology planted (fraud events) — account_takeover, card_not_present, first_party_bustout, mule_inflow, synthetic_identity. |
| `category` | Legitimate-behaviour category (non-fraud events), including adversarial mimics. |
| `label` | Ground truth: 1 = confirmed fraud; 0 = legitimate. |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only fraud-detection
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

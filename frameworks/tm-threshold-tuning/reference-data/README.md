# Reference data — TM threshold tuning

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 12 rules with 600 observations each versus 40,000 per rule at validation scale (1.5%). Threshold recommendations are distribution-dependent, so this pack illustrates input shape, not the validated operating points. The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** Two small spreadsheets — a set of monitoring rules with their current thresholds
> and per-rule observations labelled suspicious or benign — so you can see what the
> tuning engine reads before the full 40,000-observations-per-rule validation.

## `rules.csv` — 12 rows (validation scale: 12 rules)

Monitoring rules, each with a current threshold and a designed scenario.

| Column | Meaning |
|---|---|
| `rule_id` | Unique rule identifier. |
| `metric_name` | The metric the rule thresholds on. |
| `current_threshold` | The rule's current production threshold. |
| `scenario` | Ground truth: too_low (engine should RAISE), too_high (should LOWER — below-the-line leakage), or optimal (should KEEP). |

## `observations.csv` — 7,200 rows (12 rules x 600; validation scale: 12 x 40,000)

Per-rule population of observations.

| Column | Meaning |
|---|---|
| `rule_id` | Rule the observation belongs to. |
| `metric_value` | Observed metric value. |
| `label` | Ground truth: 1 = genuinely suspicious activity; 0 = benign. |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only tm-threshold-tuning
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

# Rigor contract for the frameworks pillar

What every framework's `run_validation.py` must enforce for its evidence to count.
This is the executable agreement that makes the pillar's claims defensible: the
numbers in `evidence/` are not asserted, they are emitted by a harness that fails
the build when a safety invariant is violated.

> **In plain terms:** This is the rulebook each framework's test script has to obey.
> It guarantees the proof is real — the accuracy numbers are produced by a script
> anyone can re-run, and the script refuses to "pass" if the model ever does the
> one thing it must never do (clear a real hit).

## Invariants every harness must enforce

1. **False-negative safety gate.** Compute recall on the labelled true-positive
   class. If any labelled true positive is auto-cleared, or recall falls below the
   framework's documented floor (1.0 for sanctions screening), the harness prints
   the leaked cases and **exits non-zero**. Safety is a test the build must pass,
   not a sentence in a report.

2. **Numbers are emitted, never authored.** The validation report is rendered by
   the harness from the computed results, so prose and metrics cannot diverge. No
   metric is hand-typed into a committed file.

3. **Reproducible from seed.** The population is generated from a seed recorded in
   `evidence/run-manifest.json`. Same seed + same code → identical numbers. A
   reviewer reproduces every figure by re-running.

4. **Ground truth is constructed, not assumed.** Every synthetic negative carries
   its category so per-category performance is measured against a known answer, and
   the generator plants adversarial cases (e.g. transliteration-noisy true matches)
   so the safety claim is tested against the cases designed to defeat it.

5. **Stability is demonstrable.** A multi-seed mode (`--trials`) shows the headline
   metrics across independent seeds, so the result is not a single-seed artifact.

## Required evidence artifacts

Each `evidence/` directory contains, all regenerated by the harness:

| Artifact | Contents |
|---|---|
| `VALIDATION-REPORT.md` | The prose report, rendered from real numbers, fixed section order (methodology summary → population construction → operating point → per-category → threshold sweep → false-negative safety → volume funnel → limitations → reproduction). |
| `metrics.json` | Machine-readable operating-point metrics + manifest. |
| `threshold-sweep.csv` | The full threshold-sensitivity table. |
| `confusion-matrix.csv` | TP / FP / TN / FN at the operating point. |
| `run-manifest.json` | Seed, population sizes, true-match count, git SHA, UTC timestamp, recall floor — the reproduction fingerprint. |

## CI wiring

The repository CI ([`.github/workflows/validate.yml`](../.github/workflows/validate.yml))
should, for each framework:

1. Run `python3 run_validation.py` and require exit 0 (the false-negative gate).
2. Optionally diff the freshly computed `metrics.json` against the committed one to
   catch silent metric drift.

Because the engines are pure standard library, CI needs no dependencies beyond
Python itself — consistent with the rest of the repository's validation jobs.

## What this contract is modeled on

The same discipline the repository already applies elsewhere: the `quant-jvm`
cross-language parity contract (an executable agreement enforced in CI), and the
two-file-rule validators for paste payloads. The frameworks pillar gets its own
contract because it makes a different claim — not "this prompt is self-contained"
but "this engine performs as specified, and here is the reproducible proof."

# Reference data — sanctions name screening

A small, committed sample of the synthetic input this framework's engine consumes.
It holds a 120-entry watchlist and 800 alerts versus the 4,000 / 50,000 used for validation (1.6%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** Two small spreadsheets — an invented SDN-style watchlist and the alerts a screening
> filter raised against it, labelled with the right answer — so you can see what
> the screening engine reads before the full 50,000-alert validation.

## `watchlist.csv` — 120 rows (validation scale: 4,000)

A synthetic SDN-like list. No real person, entity, vessel, or list entry is represented.

| Column | Meaning |
|---|---|
| `uid` | Unique list-entry identifier. |
| `name` | Designated party's name (invented). |
| `entity_type` | INDIVIDUAL / ENTITY / VESSEL / AIRCRAFT. |
| `program` | Invented sanctions program tag. |
| `aliases` | Known aliases (pipe-separated). |
| `dob` | Date of birth (individuals; may be blank). |
| `nationality` | Nationality (may be blank). |
| `country` | Country (may be blank). |
| `place_of_birth` | Place of birth (may be blank). |
| `passport` | Passport identifier (may be blank). |
| `national_id` | National identifier (may be blank). |
| `registration` | Company registration number (entities). |
| `imo` | IMO number (vessels). |
| `tail_number` | Tail number (aircraft). |
| `wallet` | Digital-asset wallet identifier (may be blank). |

## `alerts.csv` — 800 rows (validation scale: 50,000)

Screening alerts, each a (party x entry) pair colliding on at least one token.

| Column | Meaning |
|---|---|
| `alert_id` | Unique alert identifier. |
| `party_name` | Screened party's name. |
| `party_type` | Screened party's type. |
| `party_dob` | Party date of birth (may be blank). |
| `party_nationality` | Party nationality (may be blank). |
| `party_country` | Party country (may be blank). |
| `party_place_of_birth` | Party place of birth (may be blank). |
| `party_passport` | Party passport identifier (may be blank). |
| `party_national_id` | Party national identifier (may be blank). |
| `party_registration` | Party registration number (may be blank). |
| `party_imo` | Party IMO number (may be blank). |
| `party_tail_number` | Party tail number (may be blank). |
| `party_wallet` | Party wallet identifier (may be blank). |
| `entry_uid` | The watchlist entry the alert matched against. |
| `label` | Ground truth: 1 = true match; 0 = false positive. |
| `fp_category` | Construction category — named false-positive reason (generic, type, discriminator, weak) or true-match flavour (corroborated, name_only, noisy). |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only sanctions-name-screening
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

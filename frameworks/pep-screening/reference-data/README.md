# Reference data — PEP screening

A small, committed sample of the synthetic input this framework's engine consumes.
It holds a 150-entry list and 800 alerts versus the 8,000 / 50,000 used for validation (1.6%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** Two small spreadsheets — an invented politically-exposed-person list and the alerts
> a screening filter raised against it, labelled with the right answer — so you can
> see what the screening engine reads before the full 50,000-alert validation.

## `pep_list.csv` — 150 rows (validation scale: 8,000)

A fictional PEP list: invented officials of invented countries.

| Column | Meaning |
|---|---|
| `pep_id` | Unique list-entry identifier. |
| `name` | Listed person's name (invented). |
| `tier` | PEP tier (TIER_1 head-of-state level down to TIER_3 / RCA). |
| `position` | Invented office or position held. |
| `country` | Invented country of the office. |
| `jurisdiction_risk` | Risk bucket of that jurisdiction. |
| `status` | CURRENT or FORMER. |
| `years_since_left` | For FORMER entries: years since leaving office (drives step-down). |
| `principal_tier` | For RCA entries: the tier of the principal PEP. |
| `principal_name` | For RCA entries: the principal's name. |
| `relationship` | For RCA entries: relationship to the principal. |
| `adverse_flag` | 1 if the entry carries an adverse indicator (suspends step-down). |
| `dob` | Date of birth on the list entry (may be blank). |
| `aliases` | Known aliases (pipe-separated). |
| `name_class` | Name construction class (common vs distinctive). |

## `alerts.csv` — 800 rows (validation scale: 50,000)

Screening alerts, each a (customer x entry) pair with ground truth.

| Column | Meaning |
|---|---|
| `alert_id` | Unique alert identifier. |
| `customer_name` | Customer name as screened. |
| `customer_dob` | Customer date of birth (may be blank). |
| `customer_nationality` | Customer nationality (may be blank). |
| `pep_id` | The list entry the alert matched against. |
| `label` | Ground truth: 1 = genuine in-scope PEP match; 0 = false positive. |
| `neg_category` | Construction category — named false-positive reason (e.g. wrong_party_common_name, out_of_scope_former) or true-match flavour (e.g. corroborated_current, rca_true, adverse_former). |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only pep-screening
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

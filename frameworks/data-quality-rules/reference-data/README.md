# Reference data — data-quality rules

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 700 records versus the 50,000 used for validation (1.4%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** One small spreadsheet of made-up customer records — most clean, some seeded with
> known data defects — so you can see exactly what the quality engine reads before
> running the full 50,000-record validation.

## `records.csv` — 700 rows (validation scale: 50,000)

A synthetic customer/account extract (fictional Harborview Financial Group), one row per record, labelled with its defect class.

| Column | Meaning |
|---|---|
| `record_id` | Unique record identifier. |
| `customer_id` | Customer the record belongs to. |
| `full_name` | Customer name (blank on planted null-name defects). |
| `entity_type` | INDIVIDUAL or ENTITY (blank on planted missing-support defects). |
| `dob` | Date of birth — planted defects include malformed, calendar-false, and impossible-sequence values. |
| `country` | ISO country code — planted defects use ISO-adjacent-but-wrong codes (UK, EL, SU, ...). |
| `national_id` | National identifier — planted defects fail format or check digit. |
| `account_prefix` | Account prefix — planted defects disagree with `country`. |
| `onboarding_date` | Onboarding date. |
| `status` | Record status (ACTIVE / CLOSED) — severity of several defects depends on it. |
| `last_refresh` | Last KYC-refresh date — planted defects sit beyond the policy horizon. |
| `label` | Ground truth: 1 = critical defect (must be detected at critical severity); 0 = minor-defect or clean. |
| `category` | Construction category — the named defect class (e.g. malformed_dob, exact_dup, prefix_country_mismatch) or clean / clean_edge. |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only data-quality-rules
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

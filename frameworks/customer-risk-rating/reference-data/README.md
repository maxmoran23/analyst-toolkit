# Reference data — customer risk rating

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 800 customers versus the 50,000 used for validation (1.6%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** One small spreadsheet of made-up customers, each tagged with the risk band it was
> deliberately built to sit in, so you can see what the rating engine reads before
> running the full 50,000-customer validation.

## `customers.csv` — 800 rows (validation scale: 50,000)

Customer profiles with a KNOWN designed-risk stratum as ground truth.

| Column | Meaning |
|---|---|
| `customer_id` | Unique customer identifier. |
| `stratum` | Ground truth: the designed-risk stratum the profile was built into (designed_low / designed_medium / designed_high / hard_high). |
| `customer_type` | Customer type (individual / entity subtype). |
| `domicile_country` | Country of domicile (fictional assignment). |
| `operating_countries` | Additional operating jurisdictions (pipe-separated). |
| `products` | Products held (pipe-separated). |
| `channel` | Onboarding / servicing channel (face-to-face vs non-face-to-face). |
| `pep` | 1 if the customer is a politically exposed person (hard attribute). |
| `adverse_media` | 1 if confirmed adverse media exists (hard attribute). |
| `prior_sar` | 1 if a prior SAR was filed on the customer (hard attribute). |
| `ownership_opacity` | Ownership-transparency grade (opaque structures are a hard attribute at the top grade). |
| `expected_activity_intensity` | Expected activity intensity band. |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only customer-risk-rating
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**

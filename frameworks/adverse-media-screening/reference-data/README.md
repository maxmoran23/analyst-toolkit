# Reference data — adverse-media screening

A small, committed sample of the synthetic input this framework's engine consumes.
It holds 120 subjects and 750 hits versus the 8,000 / 50,000 used for validation (1.5%). The full validation population is regenerated from seed into `data/`
(gitignored by design — credibility is reproduction-from-seed, not data-in-repo);
this pack exists so the framework folder is fully self-contained for a reader
browsing it on its own.

> **In plain terms:** Two small spreadsheets of made-up customers and made-up news hits about them,
> labelled with the right answer, so you can see exactly what the screening engine
> reads before you run the full 50,000-hit validation.

## `subjects.csv` — 120 rows (validation scale: 8,000)

Customers being screened — a designed mix of common and distinctive names.

| Column | Meaning |
|---|---|
| `subject_id` | Unique subject identifier (join key into `hits.csv`). |
| `name` | Screened party's name. |
| `entity_type` | INDIVIDUAL or ENTITY. |
| `name_class` | Name construction class (common vs distinctive) — drives collision behaviour. |
| `country` | Subject's country (fictional assignment). |
| `dob` | Subject's date of birth (individuals). |

## `hits.csv` — 750 rows (validation scale: 50,000)

Media hits a screening tool surfaced, labelled with ground truth.

| Column | Meaning |
|---|---|
| `hit_id` | Unique hit identifier. |
| `subject_id` | Subject the hit was raised against. |
| `article_name` | Party name as printed in the article (may differ from the subject's). |
| `category` | Adverse-media category of the article (or a non-adverse topic). |
| `role` | Subject's role in the story (perpetrator / alleged / victim / passing mention). |
| `age_days` | Article age in days at screening time. |
| `art_country` | Country the article asserts for the party (may contradict the subject). |
| `art_dob` | Date of birth the article asserts (may be blank or contradicting). |
| `art_passport` | Passport identifier the article asserts (may be blank or contradicting). |
| `source_reliability` | Reliability grade of the publishing source. |
| `label` | Ground truth: 1 = genuine, material adverse-media match; 0 = false positive. |
| `fp_category` | Construction category — the named false-positive reason (wrong_entity, not_adverse, low_role, stale_immaterial, common_name_ambiguous) or true-adverse flavour (clear_adverse, emerging). |

## Regeneration

From the repository root:

```bash
python3 _tooling/build_reference_data.py --only adverse-media-screening
```

The build is deterministic (seed 42): every run reproduces these files
byte-identically, and the `reference-data` CI job re-derives and diffs them on
every change, so this pack can never silently drift from the generator.

All records are seeded synthetic data produced by this framework's own
`generate_synthetic_data.py`. No real person, entity, account, or event is
represented; any resemblance to a real name is coincidental by construction.

**Confidence: HIGH — generated by the same seeded generator as the validation population and byte-verified by the `reference-data` CI job on every change.**
